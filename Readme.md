# 📦 MAX Auto-Update System (GPO + PowerShell)

Автоматизированная система распространения и обновления приложения **MAX** в доменной среде Windows. Решение использует групповые политики (GPO) для доставки обновлений без участия пользователя и без необходимости прав локального администратора.

## 📂 Структура репозитория

| Файл | Назначение | Где запускать |
|------|------------|---------------|
| `Update-MaxPackage.ps1` | **Серверный скрипт.** Скачивает актуальный `.msi` с сайта вендора и обновляет файл в общей папке SYSVOL. | На сервере или ПК администратора (по расписанию) |
| `Install-Max.ps1` | **Клиентский скрипт.** Проверяет версию, устанавливает обновление и запускает приложение. | На клиентских ПК (через GPO Logon Script) |

## 🚀 Как это работает

### 1. Серверная часть (`Update-MaxPackage.ps1`)
Этот скрипт должен выполняться регулярно (например, раз в сутки через Task Scheduler).
*   Скачивает новую версию `MAX.msi` по защищенному каналу (TLS 1.2).
*   Сохраняет её во временный файл (`MAX.msi.new`).
*   Выполняет **атомарную замену** основного файла через `Move-Item`.
*   Если файл занят другим процессом (например, репликацией AD), скрипт повторяет попытку несколько раз с интервалом.

### 2. Клиентская часть (`Install-Max.ps1`)
Этот скрипт назначается как **Logon Script** в групповой политике пользователя.
*   При входе пользователя скрипт проверяет текущую установленную версию (читая метаданные `.exe`) и версию в новом пакете (через COM-объект MSI).
*   **Если версии совпадают:** Просто запускает приложение.
*   **Если есть новая версия:**
    1.  Закрывает работающий процесс `max.exe`.
    2.  Копирует MSI во временную папку пользователя (`%TEMP%`).
    3.  Запускает тихую установку (`msiexec /qn`) с флагом `MSIINSTALLPERUSER=1` (установка в контексте пользователя, без UAC).
    4.  После установки запускает приложение.

## ⚙️ Настройка перед использованием

Откройте оба скрипта в текстовом редакторе и измените переменные в блоке `--- Settings ---` под вашу инфраструктуру.

### В `Update-MaxPackage.ps1`:
```powershell
# Путь к папке Logon Scripts в вашем домене (SYSVOL)
$TargetPath = "\\ваш-домен.local\SYSVOL\ваш-домен.local\Policies\{GUID-ПОЛИТИКИ}\User\Scripts\Logon"
```

## ✅ Преимущества решения

### Безопасность
- Используется **TLS 1.2** для загрузок
- Установка выполняется в контексте пользователя (**Per-User**), что не требует прав администратора и не вызывает запросов UAC

### Надежность
- Проверка версий предотвращает лишние переустановки
- Механизм **retry** (повторных попыток) при замене файлов на сервере защищает от ошибок блокировки файлов
- Корректная очистка COM-объектов при чтении версий MSI

### Прозрачность
- Подробное логирование всех действий
- Автоматический запуск приложения после обновления

## 📝 Логи

Для диагностики проблем используйте следующие логи:

- **Сервер**: Файл `update.log` находится в той же папке, где лежит `Update-MaxPackage.ps1`
- **Клиент**: Файл `max_update.log` создается во временной папке текущего пользователя (`%TEMP%\max_update.log`)

## 🛠️ Развертывание

1. Создайте новую GPO или используйте существующую
2. Перейдите в **User Configuration → Policies → Windows Settings → Scripts (Logon/Logoff) → Logon**
3. Добавьте скрипт `Install-Max.ps1`
4. Поместите оба файла (`Install-Max.ps1` и `Update-MaxPackage.ps1`) в папку скриптов этой политики (кнопка **"Show Files"** в редакторе GPO)
5. Настройте планировщик заданий на сервере для ежедневного запуска `Update-MaxPackage.ps1`

> **Примечание:** Убедитесь, что на клиентских машинах разрешено выполнение скриптов PowerShell (политика Execution Policy должна быть не строже `RemoteSigned`).
