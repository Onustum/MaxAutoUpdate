# Система автоматического обновления MAX (GPO + PowerShell)

## Описание проекта

Это автоматизированное решение для распространения и обновления приложения **MAX** в доменной среде Windows. Система состоит из серверного скрипта, который загружает актуальную версию установщика, и клиентского механизма, который незаметно для пользователя устанавливает обновление при входе в систему.

## Структура файлов

* `Update-MaxPackage.ps1` — **Серверный скрипт**. Запускается по расписанию на сервере или рабочей станции администратора. Скачивает новый MSI-пакет с сайта вендора и заменяет старый файл в общей папке `SYSVOL`.
* `Install-Max.ps1` — **Клиентский скрипт**. Проверяет текущую версию программы, сравнивает её с новой версией в пакете и при необходимости выполняет тихую установку.
* `LaunchHidden.vbs` — **VBScript-обертка**. Используется для скрытого запуска PowerShell-скрипта, чтобы пользователь не видел мигающего черного окна консоли при входе в систему.

## Как это работает

### Этап 1: Обновление пакета на сервере (`Update-MaxPackage.ps1`)
1. Скрипт выполняется регулярно (например, раз в сутки через Планировщик заданий).
2. Подключается к защищенному источнику (`HTTPS` / `TLS 1.2`).
3. Скачивает файл `MAX.msi` во временный файл `MAX.msi.new` в папке скриптов GPO.
4. Пытается заменить основной файл `MAX.msi` новым. Если файл занят (например, идет репликация AD), скрипт делает несколько повторных попыток с интервалом в 60 секунд.
5. Все действия записываются в лог `update.log`.

### Этап 2: Установка на компьютере пользователя
* **Инициализация:** Процесс запускается через Групповую Политику (GPO) с использованием задачи «Планировщик заданий» (Scheduled Tasks).
* **Триггер:** Задача запускается при входе пользователя в систему (с задержкой 30 секунд для стабильности загрузки ОС). Также настроен повтор каждый час, чтобы доставить обновление пользователям, которые не перезагружают компьютеры.
* **Запуск:** Выполняется файл `wscript.exe` с аргументом `LaunchHidden.vbs`.
* **Скрытие окна:** `LaunchHidden.vbs` запускает PowerShell в скрытом режиме (окно не отображается).

#### Логика установки (`Install-Max.ps1`):
1. Определяет путь к установленному `MAX.exe` и считывает его версию.
2. Считывает версию из нового MSI-файла через COM-объект Windows Installer.
3. Если версии совпадают — просто запускает приложение.
4. Если версия новая:
   * Закрывает работающий процесс `max.exe`.
   * Копирует MSI во временную папку пользователя (`%TEMP%`).
   * Запускает `msiexec` с параметрами тихой установки (`MSIINSTALLPERUSER=1`), что позволяет установить программу без прав администратора.
   * После установки запускает приложение.
5. Все шаги логируются в `%TEMP%\max_update.log`.

## Настройка перед использованием

Перед развертыванием откройте скрипты и замените следующие значения на ваши реальные данные:

* **В файле `Update-MaxPackage.ps1`:**
  * `$TargetPath` — укажите UNC-путь к папке Logon Scripts вашей политики в `SYSVOL`.
  * `$SourceUrl` — укажите прямую ссылку на скачивание `MAX.msi` с сайта вендора.
* **В файле `Install-Max.ps1`:**
  * `$MsiSourcePath` — укажите тот же UNC-путь к файлу `MAX.msi`, что и в серверном скрипте.
  * `$MaxProcessName` — имя процесса приложения (без расширения `.exe`).
  * `$TargetDir` — папка, куда будет установлено приложение (по умолчанию используется `APPDATA` пользователя).
* **В файле `LaunchHidden.vbs`:**
  * В строке `objShell.Run` укажите правильный путь к файлу `Install-Max.ps1` в вашей сети.

## Развертывание через GPO (Инструкция для администратора)

Рекомендуемый метод доставки — использование предпочтений групповой политики (**Group Policy Preferences**).

1. Откройте редактор управления групповыми политиками (GPMC).
2. Перейдите в раздел:
   `Конфигурация пользователя` -> `Настройка` -> `Параметры панели управления` -> `Назначенные задания`.
3. Создайте новое задание типа **«Немедленное задание»** (или «Задача» для Windows 7+).
4. **Вкладка «Общие»:**
   * **Действие:** Заменить.
   * **Выполнять от имени:** Зарегистрированный пользователь (`%LogonDomain%\%LogonUser%`).
   * **Права:** Выполнять с наименьшими правами (не использовать наивысшие права).
5. **Вкладка «Триггеры»:**
   * **Начать задачу:** При входе в систему.
   * **Задержка:** 30 секунд.
   * **Повторять каждые:** 1 час (бесконечно).
6. **Вкладка «Действия»:**
   * **Действие:** Запустить программу.
   * **Программа:** `wscript.exe`
   * **Аргументы:** `"\\ваш-домен\SYSVOL\...\LaunchHidden.vbs"`
7. **Вкладка «Общие параметры»:**
   * Используйте фильтрацию по уровню элемента (*Item-level targeting*), чтобы применить политику только к нужной группе безопасности (например, «Пользователи MAX»).

## Почему используется VBS?

Прямой запуск PowerShell через GPO часто приводит к появлению черного окна консоли на несколько секунд. Использование промежуточного VBScript с параметром скрытого запуска (`0`) делает процесс обновления полностью незаметным для конечного пользователя.

## Логи и диагностика

* **Серверный лог (`update.log`):**
  Находится в той же папке `SYSVOL`, где лежат скрипты. Фиксирует результаты скачивания и замены файла.
* **Клиентский лог (`%TEMP%\max_update.log`):**
  Создается во временной папке текущего пользователя. В нем можно посмотреть:
  * Какую версию нашел скрипт.
  * Была ли выполнена установка.
  * Коды возврата `msiexec` (`0` — успех, `1603` — ошибка установки и т.д.).

## Требования

* Windows 10/11 или Windows Server 2016+.
* PowerShell 5.1+.
* Разрешенное выполнение скриптов (`Execution Policy` уровня `RemoteSigned` или выше).
* Доступ клиентских машин к контроллеру домена (`SYSVOL`) и доступ к интернету (для серверного скрипта).
